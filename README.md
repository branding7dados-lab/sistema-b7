## ✦ O que é

O Sistema B7 acompanha o conteúdo da agência **do começo ao fim**. Cada cliente
tem uma **linha editorial** por mês; dela saem as **gravações**, as demandas de
**vídeo** e de **design**; o cliente **aprova** pelo portal dele; e o **status
semanal** fecha a conta dos sete dias.

<p align="center"><img src="docs/fluxo.svg" alt="Linha editorial → Gravação → Produção → Aprovação → Status semanal" width="100%"></p>

Não é um gerenciador de tarefas genérico: **cada tela conhece o fluxo da
agência**. Uma demanda de vídeo sabe de qual conteúdo da linha ela nasceu, a
gravação sabe quais roteiros vai gravar, e o status semanal se atualiza sozinho
quando o conteúdo é publicado.

## ✦ Quem usa e o que cada um vê

| Grupo | Papel | Enxerga |
|---|---|---|
| **Colaboradores** | Administrador | Tudo, incluindo contas, acessos, Gestão e configurações. |
| | Coordenador | A produção inteira da agência, sem a administração de contas. |
| | Designer | A fila de design e o contexto do briefing. |
| | Videomaker | A fila de edição, as gravações e o contexto do cliente. |
| **Parceiros B7** | Freelancers | O mesmo da função dada, marcados à parte para a gestão. |
| **Clientes** | Dono · Gestor · Equipe | Só o portal da empresa: o que foi liberado, para ver, pedir e aprovar. |

Cada função tem um **nível por módulo** (sem acesso · ver · editar · total) e
**ações** que ligam ou desligam sozinhas — por função ou só para uma pessoa.

> 🔒 As permissões valem **no banco**, não só na tela. Esconder um botão não
> protege nada: cada tabela tem regra por linha, o papel vem sempre do servidor e
> o próprio banco confere, sozinho, se alguém consegue mais do que devia.

## ✦ Como foi construído

<p align="center"><img src="docs/arquitetura.svg" alt="Aparelhos → GitHub Pages → Supabase → IA e avisos" width="100%"></p>

**Sem framework e sem etapa de compilação.** O que está no repositório é
exatamente o que roda no navegador. Publicar é dar um merge: o GitHub Pages
serve em menos de um minuto, os apps do Windows e do Android são montados pelo
próprio GitHub, e cada aparelho recebe o aviso de versão nova.

| Camada | Tecnologia |
|---|---|
| Telas | HTML, CSS e JavaScript puros · View Transitions · vidro líquido com filtro SVG |
| Banco | Supabase (PostgreSQL) · RLS · Realtime · Storage |
| Servidor | Funções Deno no Supabase (login, 2 etapas, IA, avisos, agenda, artes) |
| IA | Groq (rápido) com Gemini de reserva e para áudio e imagem |
| Avisos | Web Push · Firebase Cloud Messaging · e-mail (Brevo) |
| Apps | Electron (Windows) · Capacitor (Android) |
| Testes | Playwright: teste de fumaça que abre todas as telas + testes por módulo |

## ✦ Instalação

<details>
<summary><b>Passo a passo completo</b> — para montar uma cópia nova do zero</summary>

<br>

### 1. Criar o projeto no Supabase

Em <https://supabase.com>, crie uma conta e clique em **New project**. Dê um
nome, guarde a senha do banco e escolha a região **South America (São Paulo)**.
Espere uns dois minutos.

### 2. Criar as tabelas

No menu lateral, **SQL Editor → New query**. Abra o `supabase/sql/supabase_setup.sql` deste
projeto, cole tudo e clique em **Run**. Depois rode, na ordem, as migrações
`supabase/sql/migration_*.sql` que ainda não estiverem aplicadas.

Deve aparecer "Success". Se der erro, a mensagem costuma dizer exatamente o que
faltou.

### 3. Copiar as chaves

Em **Project Settings → API**, você precisa de dois valores:

| No Supabase aparece como | Para que serve |
|---|---|
| **Project URL** | o endereço do seu banco |
| **anon public** (ou **publishable key**) | a chave que o site usa para conversar com o banco |

> ⚠️ **Nunca copie a chave `service_role`.** Ela é secreta e daria acesso total a
> quem abrisse o site. A chave publicável é pública por natureza — essa pode.

### 4. Colocar no config.js

Abra `js/config.js` e substitua os dois `COLE_AQUI`:

```javascript
window.B7_CONFIG = {
  SUPABASE_URL: 'https://abcdefgh.supabase.co',
  SUPABASE_PUBLISHABLE_KEY: 'sb_publishable_...'
};
```

Se abrir o sistema sem isso, ele mostra uma tela explicando o que falta em vez
de quebrar.

### 5. Publicar no GitHub Pages

Suba os arquivos para um repositório e vá em **Settings → Pages**. Em
**Source**, escolha **Deploy from a branch**; em **Branch**, `main` e a pasta
`/ (root)`.

O arquivo `.nojekyll` parece inútil, mas não é: sem ele o GitHub ignora algumas
pastas. Não apague.

### 6. Criar o primeiro administrador

Siga o `docs/BOOTSTRAP.md`. O modo de bootstrap se desliga sozinho assim que existe
um administrador.

</details>

<details>
<summary><b>Rodar os testes</b></summary>

<br>

O teste de fumaça abre todas as telas num Chromium de verdade, com o banco
simulado, e falha se alguma quebrar ou abrir vazia.

```bash
cd testes
npm install
npm test
```

O GitHub roda sozinho a cada envio — veja `.github/workflows/testes.yml`.

</details>

## ✦ Publicar uma versão

Toda publicação sobe a versão, que tem três partes (detalhes em
[`VERSOES.md`](VERSOES.md)):

| Muda | Quando | Exemplo |
|---|---|---|
| o 1º número | mudança grande, que muda o jeito de usar | 3.4.2 → **4.0.0** |
| o 2º número | novidade que a equipe percebe | 3.4.2 → 3.**5**.0 |
| o 3º número | correção ou ajuste | 3.4.2 → 3.4.**3** |

O número fica em dois lugares, sempre iguais:

| Arquivo | O quê | Para quê |
|---|---|---|
| `js/auth.js` | `VERSAO = '3.0.0'` | aparece em Configurações, nas novidades e no app Android, e dispara o aviso de versão nova |
| `sw.js` | `CACHE = 'b7-v3.0.0'` | troca o cache do aparelho; sem isso o celular fica na versão velha |

Depois é só dar merge na `main`. O GitHub Pages publica em menos de um minuto e
cada aparelho recebe o aviso de atualização.

Cada pacote de mudança tem um relatório próprio (`docs/relatorios/RELATORIO_*.md`) explicando o
que mudou e por quê — são **mais de 400** até agora.

## ✦ Segurança

- **Login com verificação em 2 etapas** (e-mail ou app autenticador), entrar
  com Google e "esqueci minha senha" por e-mail de recuperação.
- **Níveis por módulo e ações por função**, com histórico de quem mudou o acesso
  de quem e uma conferência automática das regras do banco.
- **Proteção por linha em todas as tabelas.** Um cliente só alcança os dados
  dele, e só o que foi liberado para ele.
- **Nenhum segredo no repositório.** Só a chave publicável, que é pública por
  natureza. Chaves de IA, de notificação e de agenda ficam como variáveis de
  ambiente das funções de servidor.
- **Texto vindo do banco é sempre neutralizado** antes de ir para a tela, e
  links externos passam por uma peneira.

Encontrou algo? Abra uma issue privada ou fale direto com a equipe — não
descreva a falha num lugar público.
